# 引継ぎ資料

担当者が交代しても運用を続けられるようにするための文書です。
次の3点が揃っていれば、新しい担当者が運用を復旧できます。

```text
① このGitHubリポジトリ
② data/ ディレクトリのバックアップ（database.sqlite / config.json / templates/ / assets/）
③ 運用で使用していたバージョン（Gitタグ。例: v1.2.1）
```

特定の担当者の記憶やPCにしかない情報を作らないでください。新しく決めたことは、このリポジトリの `docs/` に書き足します。

## 1. プロジェクト全体構成

- 全体像: [architecture.md](architecture.md)
- X投稿 → ブラウザ拡張 → ローカルサーバ → SQLite → テンプレート → SVG / PDF / PNG / HTML
- **コード**（このリポジトリ）と、**データ・デザイン・イベント設定**（`data/`）は別物です。
  年度が変わってもコードは書き換えません。

## 2. 普段の運用方法

[operation.md](operation.md) を参照してください。要点:

1. `npm start` → <http://127.0.0.1:38471/>
2. Xの投稿詳細ページで拡張機能ボタン → 確認 → 登録
3. 管理画面で確認・修正 → ステータスを Confirmed に
4. 「一括出力」でPDF等を生成（`output/`）
5. 「バックアップ」を実行

## 3. 新年度開始方法

コードの変更は不要です。

1. 管理画面の「バックアップ」を実行する。
2. 「イベント管理」で前年度のイベントを「アーカイブ」する（データは残ります）。
3. 「新しいイベントを作成」で、イベント名・年度・管理番号の接頭辞（例: `PC2027`）・既定テンプレートを入力する。
4. 新しいデザインがあれば `data/templates/<名前>/` に置く（[template-format.md](template-format.md)）。
5. コンテスト指定のハッシュタグが変わる場合は `data/config.json` の `parser.contestHashtags` を更新し、サーバを再起動する。
6. 受付開始。管理番号は新しいイベントで 001 から振られます。

年度ごとにデータを完全に分けたい場合は、`LABEL_DATA_DIR=data/2027 npm start` のようにデータディレクトリを切り替えます。

## 4. DBバックアップ方法

- 管理画面の「バックアップ」→ `data/backups/<日時>/` に `database.sqlite` と `entries.json`
- 加えて、`data/` ディレクトリ全体を別の場所へ定期的にコピーする
- **GitHubをデータのバックアップ先にしてはいけません**（応募者の情報が含まれます）

## 5. DB復旧方法

1. サーバを停止する。
2. `data/database.sqlite` をバックアップのものに置き換える（`-wal` / `-shm` ファイルがあれば削除）。
3. `npm start`。`Database migration required.` と出たら `npm run migrate`。

DBファイルが使えない場合は、空の `data/` で起動し、バックアップの `entries.json` を「インポート」します。

## 6. テンプレート交換方法

1. 新しいテンプレート一式を `data/templates/<名前>/` に置く。
2. 必要なフォントをインストールする（または `data/assets/fonts/` に置く）。
3. 「イベント管理」で新しいイベントの既定テンプレートに指定する。
   既存イベントのテンプレートを変える場合は、一括出力のダイアログでテンプレートを選ぶか、
   `PUT /api/events/{id}` で `defaultTemplateId` を更新する。
4. プレビューで警告が出ないか確認する。

## 7. ブラウザ拡張更新方法

1. `git pull`（またはReleaseからZIPを取得）
2. `npm install && npm run build`
3. ブラウザの拡張機能管理画面で「再読み込み」を押す（Releaseの拡張機能ZIPを使う場合は展開して読み込み直す）
4. 開いているXのタブを再読み込みする

## 8. X側仕様変更時に確認する場所

[x-extractor.md](x-extractor.md) を参照。修正するのは `packages/x-extractor/index.ts` のみです。

## 9. Release作成方法

1. 変更を `main` へマージし、CIが通っていることを確認する。
2. `package.json` と `apps/extension/manifest.json` の `version` を更新する（SemVer）。
   - MAJOR: 互換性のない変更 / MINOR: 後方互換の機能追加 / PATCH: バグ修正・X仕様変更対応
3. タグを付けてpushする。

   ```sh
   git tag v1.2.3
   git push origin v1.2.3
   ```

4. GitHub Actions（`.github/workflows/release.yml`）が、拡張機能ZIPとサーバ一式ZIPを添付したReleaseを作成する。
5. **その年のコンテストで使用したバージョンを下の表に記録する。**

| イベント | 使用バージョン | 備考 |
| --- | --- | --- |
| （例）Example Photo Contest 2026 | v1.0.0 | |

年度ごとにリポジトリをforkしたり、ブランチを分けたりしないでください。

## 10. 前年度データのアーカイブ方法

- 管理画面でイベントを「アーカイブ」にする。データは削除されず、イベントを切り替えればいつでも閲覧・再出力できます。
- 長期保管用に、「JSON出力」「CSV出力」の結果と `data/` のコピーを団体の保管場所へ保存します。
- 保存期間・削除の方針は団体の個人情報の取り扱いに従ってください。

## 11. トラブル時の手動運用方法

拡張機能やXの取得が使えなくても、キャプション生成は止まりません。

| 手段 | 方法 |
| --- | --- |
| 手入力 | 管理画面の「＋ 手動登録」（または拡張機能の「手動入力」） |
| CSV | スプレッドシートで作成 →「インポート」（列名は [operation.md](operation.md)） |
| JSON | `examples/entries.example.json` と同じ形式 →「インポート」 |

サーバ自体が起動しない場合は、エラーメッセージを確認し、[setup.md](setup.md) の手順で別のPCに環境を作り、
`data/` のバックアップを置いて起動してください。

## 引継ぎ時のチェックリスト

- [ ] リポジトリへのアクセス権を新しい担当者へ付与した
- [ ] `data/` の最新バックアップを安全な方法で渡した（メール添付や公開の場所は避ける）
- [ ] 使用バージョンの表（上記 9.）を更新した
- [ ] 必要なフォントと入手先を伝えた
- [ ] 新しい担当者のPCで `npm start` と出力まで確認した
